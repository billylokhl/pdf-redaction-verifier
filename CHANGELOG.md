- `--version` flag to display tool version
- Tokenization of leftover content streams (compact inline images, long/compactly written text)
- Case library (`eval/caselib`) with parameter grids and raw-writer cases for robust testing

- Provenance sidecars for committed real-tool files (`eval/caselib/real/*.json`), a privacy scrub over every committed binary (raw bytes, decompressed streams, decoded PDF string tokens including UTF-16 and hex strings, metadata, and XMP), a blind red-team case slot (`eval/caselib/redteam/`) with frozen, adjudicated labels, and a gallery-fields ratchet (`mistake`/`recovery` required on leak cases)

No change to `verify.py`'s own behavior or verdicts.

- **Redesign Phase 3a, PR 3a-1: ledger types, budget and byte tiling** (#32), in shadow mode — nothing the CLI ships imports them. `redaction_verifier/ledger.py` (re-exported from `redaction_verifier/model.py`) holds the frozen ledger types of `docs/REDESIGN.md` §4 (`Status`, `NAReason` with exactly ADR 0003's four reasons, a closed `FlagReason`, `UnitKind`, `UnitRef`, `Span`, `Flag`, `Unit`; a `Flag` carries only named plain integers, never document bytes); the legacy types are untouched. `redaction_verifier/budget.py`: `Limits` (ADR 0006's placeholders — depth 25, 200,000 units, 2 GiB inflated, 200 Mpx OCR per page times the anchored page count, capped at a flat 20 Gpx — plus named parse limits) and a `Budget` that never raises and reports exhaustion as a flag. `redaction_verifier/inventory/`: `tile()`, which partitions every byte of a file into owned, contested, whitespace or unindexed regions in O(n) regions and flags for n claims (a contested run is one region listing at most 16 owners beside its true claimant count) and flags contested bytes, non-whitespace unclaimed bytes, out-of-range claims, invalid claims (nested refs, gap kinds, top-level claims of the nested-only kinds) and a unit's partial self-overlap — its sweep compacts its active set so a crowd of simultaneous claimants cannot make the rest of the sweep quadratic — and `check_tiling()`. Hypothesis (pinned in the `test` extra; a derandomized `ci` profile is the default under `CI`) property-tests both; new import guards keep the inventory out of the CLI and the secret-holding modules (child-side code may import only an allowlist of a few standard-library modules and the child-side package itself, and may not mention `exec`, `eval`, `compile`, `__import__` or the `sys` import machinery by name, attribute or string) out of the child-side code; mypy is strict on the new modules. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-2: lexer and string decoding** (#34), in shadow mode. `redaction_verifier/inventory/lexer.py` tokenizes per ISO 32000-1 §7.2–7.3: tokens carry only a kind and a byte span, every byte lands in one token or in whitespace between tokens, it never raises and runs in linear time, and each anomaly is a flag on its token (new `FlagReason`s `UNTERMINATED`, `INVALID_HEX_DIGIT`, `INVALID_NAME_ESCAPE`, `STRAY_DELIMITER`). `redaction_verifier/inventory/strings.py` decodes literal, hex and name tokens and text strings (UTF-16BE, UTF-16LE — outside the spec, but shown as text by real readers — or UTF-8 by byte-order mark, with language tags removed but the tagged text kept beside it; else PDFDocEncoding; raw bytes kept); its literal decoder follows §7.3.4.2 exactly, fixing in the new code the two end-of-line bugs of the legacy `verify._decode_pdf_string` (a backslash-end-of-line continuation now contributes nothing; an unescaped CR, LF or CR LF is one LF). The legacy decoder is untouched. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-3: object parser** (#36), in shadow mode. `redaction_verifier/inventory/objects.py` parses values and indirect objects (`N G obj ... endobj`, streams included) iteratively on top of the lexer: every value keeps its byte span; nothing raises; ambiguity is flagged, never resolved silently — a repeated dictionary key (`DUPLICATE_KEY`, recording whether the values are textually identical per ADR 0002; `PdfDict.get` refuses a key whose repeats differ), a `/Length` that disagrees with `endstream` (`LENGTH_MISMATCH`, falling back to the scan), anything but one end-of-line between `/Length` and `endstream`, whitespace included, since MuPDF reads it as data (`STREAM_SLACK`), `endstream` run into `endobj`, where MuPDF and qpdf read different stream lengths (`ENDSTREAM_JOINED`), tokens after the value (`EXTRA_TOKENS`), a missing `endobj`; a token that fits nowhere is kept as a decoded, flagged stray. Tokens, nesting depth, number length and flags are capped per object by new `Limits`. On the case library's 402 files, 8,946 objects parse with no flag and every stream read at an xref offset matches MuPDF's raw read. The child-side import guard now also bans the standard library's string evaluators (`typing.get_type_hints`/`ForwardRef`, `inspect.get_annotations`, `dataclasses._create_fn`), every module reachable as an attribute of an allowed one (`dataclasses.functools`, `typing.sys`, ..., computed on the running Python) and banned names imported from allowed modules (#35). Verdict changes: none.

- **Redesign Phase 3a, PR 3a-5: `build_inventory`**, in shadow mode. `redaction_verifier/inventory/build.py` attributes every byte of a file to a unit or flags it, from the canonical xref chain only: the header line and the comment lines after it; each classic table; every revision's `startxref N %%EOF`; every distinct in-use offset of every revision (cross-reference streams included), parsed once and bounded by the next known start so no parse can run on into the rest of the file; stream slack as a nested unit; and, scanning only the unclaimed gaps, linearly, the `N G obj` bodies no xref reaches (`DEAD_BODY`). All 402 case-library files inventory and tile; every revision of the 398 unflagged ones agrees with qpdf and MuPDF on the object set, raw stream data, object-stream member values and dead bodies (the other 4 are the after-`%%EOF` leak cases, flagged); generated and mutated files are flagged or agree; adversarial inputs run in linear time. Verdict changes: none.

- **Redesign Phase 3a, PR 3a-7b: the page tree and page attributes** (ADR 0011 item 2; closes #77), in shadow mode. `redaction_verifier/inventory/pages.py` reads each revision's page tree from the catalog's `/Pages` and accepts only the canonical shape both readers read alike -- an indirect `/Type /Pages` root with `/Kids` and no `/Parent`; every node a dictionary reached by one indirect reference in one `/Kids`; `/Type` matching `/Kids`; `/Count` the pages below; `/Parent` the listing node; at most 100 levels -- and each page's `/Resources`, `/MediaBox`, `/CropBox` and `/Rotate`, nearest ancestor first: found where required, not a reference to null or nothing, a dictionary, four numbers with positive area in MuPDF's 32-bit floats -- the media box, and its intersection with the crop box, at least one unit wide and tall (MuPDF otherwise shows a 1x1 or 612x792 page where qpdf keeps the box) -- a multiple of 90; no `/UserUnit` other than 1 on the page itself (MuPDF scales the page by it, and does not inherit it); no `/ArtBox`, `/TrimBox`, `/BleedBox` on a `/Pages` node; `/Contents` absent, a stream or an array of streams; at least one page (qpdf `--check` fails on none). ### Fixed
- **CI tests Python 3.13 and 3.14** (#79): `requires-python` is open-ended and `uv sync` succeeds on 3.14, but CI tested only 3.10 and 3.12, so a 3.13/3.14-only failure (the import guard's, below) stayed green. The Linux `partial-linux` matrix gains 3.13 and 3.14 (qpdf 12.4.2, matching pikepdf 10.16.0's libqpdf), and `uv.lock`'s required environments widen from below 3.14 to below 3.15, as does `environment.yml`'s Python pin; no locked package version changes. The macOS job stays on 3.12. Verdict changes: none.
- **Text layer: the visible area on rotated pages, and values across its edge (closes K9).** The Text layer computed the visible area (the crop box ∩ the media box, where PyMuPDF puts the origin of the glyphs it reports, whatever the rotation) by derotating `page.rect`, which has the right size but, on a page with `/Rotate` 90, 180 or 270, the wrong offset when the crop box reaches past the media box, when `/UserUnit` is not 1, or when the crop box misses the media box (MuPDF then falls back to a 612x792 frame). Visible text was put in the off-page reading, and a line crossing the miscomputed edge was split between the two readings, so a value on it matched in neither. The visible area is now the derotated size at the origin. Readings 0-3 keep their meaning; on such pages their content changes, as text moves to the reading it belongs in. **Binary layer: the `/ID` qpdf generates is not scanned** (`verify.py`): with `--deterministic-id` ("Clock-dependent Binary warning" above) qpdf's own document `/ID` in its QDF output no longer changes between runs, but it is still not in the file. qpdf keeps the file's first element and generates the second (both, if the file has none or its first element is empty). The rare file whose generated `/ID` happens to spell a short all-hex value rule was therefore flagged (`REVIEW_BINARY`, exit 2) on every run. The `/ID` elements qpdf generated are now blanked in its final trailer before the Binary scan, judged against the input's own `/ID` elements (hex or literal strings, every `/ID` in the file).

Blanking is narrow by design: only a trailer of qpdf's exact shape at the very end of its output, holding exactly one `/ID`, and only elements that are none of the input's own. The input must also account for qpdf's first element. Either it is one of the input's own (qpdf keeps a non-empty first element), or no `/ID` was found in the input and qpdf's two elements are identical, as qpdf writes them when it generates both. That second rule covers `/ID` keys the parser misses but qpdf reads (`/I#44`, `/ID` followed by NUL): qpdf keeps the file's first element there and generates a different second one, so nothing is blanked. Anything else, including an `/ID` in the input that cannot be read, leaves the bytes as they are, so a mistake costs at most a false alarm, now a repeatable one. The input's `/ID` keys are searched once each, so a file built of nested `/ID [(` runs cannot make the search quadratic. The last 64 KiB of qpdf's output are held back until qpdf finishes, so the trailer is whole, and are then scanned in order. Tests are in `tests/test_objects.py::TestQpdfGeneratedId`:
- a value found only in qpdf's generated `/ID` is never reported;
- one in the input's own `/ID` still is, including behind a `/I#44` or `/ID`+NUL key, end to end with real qpdf;
- a match split by the hold boundary is still found.

### Verdict changes
The following changes can move a file's exit code:
- **Exit 0 or 2 → 1** (Text layer across the visible edge, #68): a font-coded value running across the edge of the visible area (crop box ∩ media box), written vertically off the page, or split at a page break whose first half is the visible text's last line read on past the edge, is now a Text finding; a visible line on a rotated page with an overhanging crop box, `/UserUnit` other than 1 or an empty crop ∩ media box is read as visible. **Exit 0 → 2**: a value formed by visible and off-page parts — a page-break split with either half wholly off the page, a value wrapped onto a line wholly off the page, or a visible and an off-page part a column break apart on one line — is now manual review at every rotation (owner decisions, 2026-10-10 and 2026-10-11), and so is a value split around a header, footer or page number, inside one column of a two-column page, or with its halves in reverse order (2026-10-11), by design also on the odd clean page whose visible text and an off-page slug happen to form one. **Exit 0 → 1, a known false alarm**: a slug a word space past visible text at the page edge that, with the next page's first line, forms a value (`false-alarm.slug-beside-visible-line`). **Exit 1 → 2, where main was right by accident**: on a rotated page whose crop box does not sit on the media box, the same off-page layouts (and vertically written text split at a page break with a half off the page) were findings only because main's misplaced visible area put the off-page part on the page; they are manual review now (owner decisions, 2026-10-10 and 2026-10-11). **Exit 2 → 0, owner-approved known gaps (2026-10-12)**: on rotated pages, a letter-spaced value in fine print broken into one-character lines around a header, a value wrapped over two fine-print lines closer than the line tolerance, and a page-break split whose halves are written in different directions with a half off the page, which main flagged only because its misplaced visible area read them apart or put them on the page; all three exit 0 at `/Rotate` 0 on main too.
- **Exit 2 ↔ 0, at random → never** (qpdf `--deterministic-id`): a clean file with a short all-hex value rule no longer exits 2 on some runs and 0 on others from a coincidental match in qpdf's clock-seeded `/ID`. qpdf's `/ID` is now derived from the file, so the rare file whose `/ID` contains such a value exits 2 on every run instead (manual review, never a hard finding). When the match is in an element qpdf generated (not the file's own) and that element can be told apart from the file's, the file now exits 0 instead ("Exit 2 → 0, Binary layer, qpdf's generated `/ID`" below).
- **Exit 0 → 2**: Files with compactly written content streams (no spaces between operators), long inline images or text in leftover streams without BT operators, or font-before-BT patterns in leftover streams (now properly tokenized). The scanner cannot certify these files as fully clean because it cannot reliably extract the content.
- **Exit 2 → 0 or 1, macOS 27 only**: OCR used to fail on every page there (`PAGE_FAILED`), so every file without a finding from another layer exited 2 (a leak another layer found still exited 1). OCR now reads those pages: a clean file can exit 0, and a leak found only by OCR now exits 1. Nothing changes on macOS 26 (CI's `macos-latest` image), where the old options did not fail, or on Linux, where OCR is unavailable.
- **Exit 0 → 2**: A page where Vision reports success but a request's completion handler never ran to the end, or saw no results, is now `PAGE_FAILED`; it used to count as read with nothing on it. If another layer found a leak, the run still exits 1. Not observed with real Vision on macOS 26 or 27.
- **Process abort → exit 2**: An exception inside a Vision completion handler used to abort the process (killed by `SIGABRT`, no exit code of ours, no report). The page is now `PAGE_FAILED` and the run exits 2, or 1 if another layer found a leak. Not observed in normal use; reproduced by making a handler raise.
- **Exit 0 → 2**: A custom pattern rule that needs a run of separators (`REF--\d{6}`) and matches only a line of a reconstructed reading (the Text layer's column readings, OCR's raw readings) is now manual review; collapsing separators had hidden it.
- **Exit 1 → 2, macOS only**: A file whose only hard finding was OCR's, in a line Vision read vertically that no upright re-read confirms, is now manual review: on macOS 27, a one-character-per-line stack read as one line (a pattern match on a misread number); rarely a rotated value whose re-read differs (4 of 692 in the measurement above; in a 1,080-page sweep of a line slanted 30–60° in each quadrant, 10 of the 1,047 lines Vision read, mostly 7 pt near a page edge); and on a page of sideways text, the vertical lines past the page's 64 re-reads. On CI's macOS 26 the four `layout.vertical-stack` cases named under Fixed already exited `2`; what Vision there returns for a stack was not measured. Nothing changes on Linux, where OCR is unavailable.
- **Exit 0 → 1 or 2, trailer strings**: A secret in the document trailer's `/ID`, in a private trailer key under a pattern rule, or in an earlier revision's trailer is now found: exit 1, or 2 for a pattern-rule match in a `/ID` element made only of hex digits and dashes. A clean file whose `/ID` is written as hex text that happens to contain a run a pattern class accepts now exits 2 under that pattern rule (none in the 2,073-file local corpus); a trailer dictionary that never closes, or a cross-reference section the chain reaches whose trailer cannot be read, is a `TRAILER_UNREADABLE` warning (exit 2), and a trailer string literal that never closes is `UNTERMINATED_STRING` (exit 2). A comment inside a trailer is read as raw text at the manual-review tier (`REVIEW_OBJECT_TEXT`).
- **Exit 0 → 1 or 2, earlier revisions behind a commented trailer**: the earlier-revision walk now skips comments inside a trailer dictionary, so a `>>` in a comment no longer cuts the dictionary short and loses its `/Prev`.
- **Exit 1 or 0 → 2, malformed sections**: the earlier-revision walk now reads a section the way PDF does: comments are skipped (a `%` in a name, such as `/X%Y`, starts one), the `trailer` keyword must come right after the table and be followed by the dictionary. A malformed file where junk follows the table or the keyword (qpdf also rejects these) loses that section and the earlier revisions behind it: `TRAILER_UNREADABLE`, exit 2 even on a clean file, and a secret found only there moves from 1 to 2 (never 0).
- **Exit 1 → 2, a malformed newer table read differently**: a newer table whose header was split across lines (`7` then `1 0000000617` then `00000 n`) used to be read, by accident, as the two-integer line `1 0000000617` (objects 1-617); it is now read as the one object it declares, so an earlier version of an object the table does not list is no longer compared. Such files are malformed (MuPDF repairs them, qpdf exits 3), so the run exits 2, not 0.
- **Exit 2 → 1, an overlong subsection header**: a header number longer than 10 digits now reads as a table of the wrong shape (every object compared), so a secret in an earlier revision behind it is found. Over 4,300 digits it used to crash the Objects layer (`LAYER_CRASHED`, exit 2); below that it was read as a range that could miss the rewritten object (exit 2 only through qpdf's warning).
- **Exit 0 → 1, earlier revisions behind odd subsection headers**: a newer section whose subsection header holds a comment or NUL, or whose entries share one line, used to name no rewritten objects, so the earlier versions were never compared; they now are.
- **Exit 2 → 1, private trailer keys**: A known value in a private trailer key, which only the Binary layer's manual-review warning caught, is now a hard finding.
- **Label only, cross-reference streams**: A match in a cross-reference stream's dictionary is still exit 1 (hard), now labelled as the trailer (`live` or `superseded`) instead of `ORPHANED object N`, except a pattern-rule match in an element of the dictionary's own `/ID` (its top-level key, not one in a nested dictionary, array or comment) made only of hex digits and dashes, which moves 1 → 2 (manual review).
- **Exit 2 → 0, Binary layer, qpdf's generated `/ID`**: A file flagged on every run only because the `/ID` qpdf generates for it (now deterministic, see above) spells a short all-hex value rule is no longer flagged for it, wherever the generated elements can be told apart from the file's own. Where they cannot (the input's `/ID` cannot be read, or the interlock fails, as for a file whose first `/ID` element is empty, which qpdf replaces), they are still scanned, the same on every run. One constructible case also goes 2 → 0: a file whose own `/ID` element is byte-for-byte the `/ID` qpdf generates for it, written under an `/ID` key the raw parse does not reach (a spelling such as `/I#44`, or a key that falls inside an earlier `/ID` array's string), has that element blanked. That element is MD5 output qpdf derives from the file, so making it carry a chosen value means brute-forcing MD5 (about 2^31 tries for a 9-digit value); the Objects layer's own trailer reading (K40) is unaffected.
- **Exit 1 → 2**: An unexpected internal error in the tool now exits 2 (uncertifiable) unless a secret had already been found, in which case it stays 1 (leak). The JSON report includes `error.code` as `INTERNAL_ERROR` when applicable.
