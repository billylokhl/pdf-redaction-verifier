## Unreleased

### Added
- `--json` report output format for machine-readable scan results
- `--version` flag to display tool version
- Tokenization of leftover content streams (compact inline images, long/compactly written text)
- Case library (`eval/caselib`) with parameter grids and raw-writer cases for robust testing
- Scorecard (`eval/scorecard`): a per-case differential of the CLI against a pinned reference version (environment-independent: drops OCR/tool-availability noise, and every accepted difference must be tracked in `eval/accepted_diffs.yaml`, with a `weaker: true` flag required on any verdict-loosening entry and a check for entries no case still produces), label-based metrics (silent miss, downgrade, false hard, review rate, crash/timeout, runtime), and a local-only, path-guarded real-world corpus for clean-side metrics (producer family only, never the raw `/Producer` string)
- Provenance sidecars for committed real-tool files (`eval/caselib/real/*.json`), a privacy scrub over every committed binary (raw bytes, decompressed streams, decoded PDF string tokens including UTF-16 and hex strings, metadata, and XMP), a blind red-team case slot (`eval/caselib/redteam/`) with frozen, adjudicated labels, and a gallery-fields ratchet (`mistake`/`recovery` required on leak cases)
- `eval/check_ratchets.py` and a CI job comparing every "may only shrink" allowlist and the red-team slot's frozen label anchor against the merge-base with `main` (or `HEAD~1` on a direct push), so a list and its own same-commit consistency check can no longer move together undetected
- Case library: pinned cases for every remaining `UNDOCUMENTED_GAPS` cell (24 silent misses and one false alarm) plus one new gap found while reviewing them (`live.font.overprinted`) — 25 silent misses total, documented as K12-K36 in `docs/REDESIGN.md` §8 — and three large `perf`-marked performance fixtures (a ~300-page scanned document, a ~500-page text document, a ~50 MB image-heavy file), run only with `RUN_PERF=1`. No change to `verify.py`'s own behavior or verdicts.
- Gallery (`eval/gallery`, `docs/REDESIGN.md` Phase 0e): a static, self-contained HTML page generated from the case library — the mistake, the recovery method, a page-1 render, the pinned (fabricated) secret and today's verdict for every leak case, with a clear marker on each one today's tool still certifies clean, plus a section for clean and false-alarm cases. `PYTHONPATH=eval:. python -m gallery build --out DIR [--results FILE]`; nothing it generates is committed, and it never gates anything — a non-gating CI job builds it and uploads it as an artifact. No change to `verify.py`'s own behavior or verdicts.
- **Redesign Phase 3a, PR 3a-1: ledger types, budget and byte tiling** (#32), in shadow mode — nothing the CLI ships imports them. `redaction_verifier/ledger.py` (re-exported from `redaction_verifier/model.py`) holds the frozen ledger types of `docs/REDESIGN.md` §4 (`Status`, `NAReason` with exactly ADR 0003's four reasons, a closed `FlagReason`, `UnitKind`, `UnitRef`, `Span`, `Flag`, `Unit`; a `Flag` carries only named plain integers, never document bytes); the legacy types are untouched. `redaction_verifier/budget.py`: `Limits` (ADR 0006's placeholders — depth 25, 200,000 units, 2 GiB inflated, 200 Mpx OCR per page times the anchored page count, capped at a flat 20 Gpx — plus named parse limits) and a `Budget` that never raises and reports exhaustion as a flag. `redaction_verifier/inventory/`: `tile()`, which partitions every byte of a file into owned, contested, whitespace or unindexed regions in O(n) regions and flags for n claims (a contested run is one region listing at most 16 owners beside its true claimant count) and flags contested bytes, non-whitespace unclaimed bytes, out-of-range claims, invalid claims (nested refs, gap kinds, top-level claims of the nested-only kinds) and a unit's partial self-overlap — its sweep compacts its active set so a crowd of simultaneous claimants cannot make the rest of the sweep quadratic — and `check_tiling()`. Hypothesis (pinned in the `test` extra; a derandomized `ci` profile is the default under `CI`) property-tests both; new import guards keep the inventory out of the CLI and the secret-holding modules (child-side code may import only an allowlist of a few standard-library modules and the child-side package itself, and may not mention `exec`, `eval`, `compile`, `__import__` or the `sys` import machinery by name, attribute or string) out of the child-side code; mypy is strict on the new modules. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-2: lexer and string decoding** (#34), in shadow mode. `redaction_verifier/inventory/lexer.py` tokenizes per ISO 32000-1 §7.2–7.3: tokens carry only a kind and a byte span, every byte lands in one token or in whitespace between tokens, it never raises and runs in linear time, and each anomaly is a flag on its token (new `FlagReason`s `UNTERMINATED`, `INVALID_HEX_DIGIT`, `INVALID_NAME_ESCAPE`, `STRAY_DELIMITER`). `redaction_verifier/inventory/strings.py` decodes literal, hex and name tokens and text strings (UTF-16BE, UTF-16LE — outside the spec, but shown as text by real readers — or UTF-8 by byte-order mark, with language tags removed but the tagged text kept beside it; else PDFDocEncoding; raw bytes kept); its literal decoder follows §7.3.4.2 exactly, fixing in the new code the two end-of-line bugs of the legacy `verify._decode_pdf_string` (a backslash-end-of-line continuation now contributes nothing; an unescaped CR, LF or CR LF is one LF). The legacy decoder is untouched. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-3: object parser** (#36), in shadow mode. `redaction_verifier/inventory/objects.py` parses values and indirect objects (`N G obj ... endobj`, streams included) iteratively on top of the lexer: every value keeps its byte span; nothing raises; ambiguity is flagged, never resolved silently — a repeated dictionary key (`DUPLICATE_KEY`, recording whether the values are textually identical per ADR 0002; `PdfDict.get` refuses a key whose repeats differ), a `/Length` that disagrees with `endstream` (`LENGTH_MISMATCH`, falling back to the scan), anything but one end-of-line between `/Length` and `endstream`, whitespace included, since MuPDF reads it as data (`STREAM_SLACK`), `endstream` run into `endobj`, where MuPDF and qpdf read different stream lengths (`ENDSTREAM_JOINED`), tokens after the value (`EXTRA_TOKENS`), a missing `endobj`; a token that fits nowhere is kept as a decoded, flagged stray. Tokens, nesting depth, number length and flags are capped per object by new `Limits`. On the case library's 402 files, 8,946 objects parse with no flag and every stream read at an xref offset matches MuPDF's raw read. The child-side import guard now also bans the standard library's string evaluators (`typing.get_type_hints`/`ForwardRef`, `inspect.get_annotations`, `dataclasses._create_fn`), every module reachable as an attribute of an allowed one (`dataclasses.functools`, `typing.sys`, ..., computed on the running Python) and banned names imported from allowed modules (#35). Verdict changes: none.
- **ADR 0010: readers are the authority; agreement is the gate** (docs only). After repeated Phase 3a review rounds, a design review found the architecture sound but the parser named as the authority; the owner adopted every recommendation: the parser certifies that MuPDF and qpdf agree instead of choosing a reading, 3a's gate becomes zero unflagged disagreements with both readers, linear time is enforced by a work budget, 3a-4 accepts only canonical xref chains, a minimal secret-free child process moves into 3b, and review findings block a merge only when major (the rest become issues). REDESIGN §4 and §7 and the Phase 3a plan are updated. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-3b: reader-agreement fuzzing and a work budget** (#39), per ADR 0010, in shadow mode. `tests/test_inventory_differential.py` generates PDFs whose stream framing and dictionary values vary in the details readers are known to disagree on (not yet: huge numbers, long reals, out-of-range references -- #40), reads them with our parser, MuPDF and qpdf, and fails on any disagreement the parser does not flag; `ACCEPTED_LENIENCIES` is the written allowlist of off-spec inputs accepted unflagged, each with a test showing both readers agree. It found two: a lone CR after `stream` (qpdf warns) and `#00` in a name (MuPDF keeps it literally, qpdf rejects it) — both now flagged. A file-wide work budget (`Limits.work_per_byte`, `Budget.charge_work`) charges every byte the parser or a scan passes over and refuses up front once spent, so a superlinear path is flagged `BUDGET_EXHAUSTED` instead of hanging; linearity is tested by work counts and by wall-clock runs on adversarial offsets. `TextString.lossless` reports decodes that replaced bytes. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-4a: capped FlateDecode with predictors** (#41), in shadow mode, for the inventory's own reads of xref and object streams. `redaction_verifier/inventory/flate.py` decodes only the canonical case without a flag — a complete zlib stream with a good checksum, every input byte consumed, whole predictor rows with valid row types; anything else keeps its output and is flagged (`FLATE_ERROR`, `FLATE_TRUNCATED`, `AFTER_STREAM_END`, `BAD_DECODE_PARMS`, `PREDICTOR_ERROR`). Output is charged to the run's inflated-bytes budget as it is produced, so a decompression bomb stops at the cap. Unflagged decodes match MuPDF and qpdf byte for byte in differential fuzzing. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-4b: the canonical cross-reference chain** (#43), in shadow mode, per ADR 0010 item 4. `redaction_verifier/inventory/xref.py` follows `startxref`, `/Prev` and hybrid `/XRefStm` through classic tables and cross-reference streams and reports every revision's object map, accepting only canonical shapes and emulating no reader's repair: anything else is flagged and the file cannot be certified (`HEADER_OFFSET`, `XREF_TAIL`, `XREF_NOT_FOUND`, `XREF_TABLE_MALFORMED`, `XREF_STREAM_MALFORMED`, `UNSUPPORTED_FILTER`, `XREF_CONFLICT`, `XREF_OFFSET_MISMATCH`, `PREV_CYCLE`, `MISSING_ROOT`, `XREF_SIZE_MISMATCH`). Every revision of 398 case-library files matches qpdf's and MuPDF's object maps; the case library's four "data after the final `%%EOF`" leak cases are flagged; an exhaustive single-byte mutation sweep finds no unflagged disagreement with the readers. A forward `/Prev` is accepted only in the linearized shape, and a revision that frees an object stream its older members still live in is flagged. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-5: `build_inventory`**, in shadow mode. `redaction_verifier/inventory/build.py` attributes every byte of a file to a unit or flags it, from the canonical xref chain only: the header line and the comment lines after it; each classic table; every revision's `startxref N %%EOF`; every distinct in-use offset of every revision (cross-reference streams included), parsed once and bounded by the next known start so no parse can run on into the rest of the file; stream slack as a nested unit; and, scanning only the unclaimed gaps, linearly, the `N G obj` bodies no xref reaches (`DEAD_BODY`). Every in-use object stream is decoded and its header table and members tiled in their own coordinates; every compressed entry of every revision must find its member in that revision's home, and a compressed `/Root` must be a clean catalog. `Inventory.body(n, revision)` and `bodies_by_number(revision)` give each object's body per revision. New flags `XREF_EPILOGUE_MISMATCH`, `REVISION_AMBIGUOUS` (an indirect `/Length` that changes while its stream lives), `OBJSTM_MALFORMED`, `OBJSTM_MEMBER_INVALID` (including an object-stream member the readers read otherwise: a bare `null`, which MuPDF takes for a missing object and repairs the file around, a lone `N G R`, or a token running across `/First` or a member's bound), `OBJSTM_ENTRY_MISMATCH`; flags are capped per file (`Limits.max_flags_per_file`). `read_chain` now requires a `Budget`, and its own object checks resolve an indirect `/Length` (every such stream was flagged before). `python -m redaction_verifier.inventory FILE` prints a JSON summary of counts, never document bytes; the child-side import guard lets that one dev entry point import `json` and `sys`, and nothing may import it. All 402 case-library files inventory and tile; every revision of the 398 unflagged ones agrees with qpdf and MuPDF on the object set, raw stream data, object-stream member values and dead bodies (the other 4 are the after-`%%EOF` leak cases, flagged); generated and mutated files are flagged or agree; adversarial inputs run in linear time. Verdict changes: none.
- **Redesign Phase 3a, PR 3a-6: the inventory agreement gate**, in shadow mode, per ADR 0010. `python -m scorecard inventory run --root DIR` checks the SHA-pinned local corpus manifest (a drifted corpus is refused), then builds each file's inventory in a child process with a 60 s timeout and compares it with MuPDF and qpdf in a second child. The gate fails on any unflagged disagreement (by failed check: object set, stream data, member value, dead bodies, qpdf `--check`, MuPDF warning or repair, tiling), crash, timeout, or unflagged file the comparison could not finish. Flag rates, UNINDEXED/CONTESTED regions and the owner's pending decisions (#44, #46) are reported, never gated. `inventory caselib` and `inventory fuzz` run the same gate over the case library and generated files. Output is aggregate counts only; per-file detail stays in the gitignored `eval/scorecard/real_corpus/`. The tests' reader differential moved into `eval/scorecard/inventory.py` so there is one oracle; it now compares every object-stream member with MuPDF, reading MuPDF's pretty print (its tight print runs an empty name into the next token). Case library: 394 agree, 4 flagged, 0 unflagged disagreements. Fuzz: 740 agree, 2,260 flagged, 0 unflagged disagreements. Verdict changes: none.

### Fixed
Four bugs found by a post-merge adversarial review, all in the eval/gallery tooling — no change to `verify.py`'s own behavior, verdicts, or case content:
- **`eval/check_ratchets.py`**: a "may only shrink" allowlist (`UNDOCUMENTED_GAPS`, `NONFITZ_PENDING`, `GALLERY_FIELDS_PENDING`) could be grown undetected by rebinding its name after the literal the check reads — a second assignment, one inside an `if`/`try`/`with` block, unpacking, a `for`/walrus/`with ... as` target, `global` in a function called at import, `globals()`/`vars()`/`locals()` subscripts or `.update(NAME=...)`, `setattr(sys.modules[__name__], ...)`, `exec`, an import alias, `except ... as`, a `match` capture, a class body, `def NAME`, a star import — or by rebinding it in `eval/caselib/__init__.py`, which tests import the sets through and no check looked at. The check now walks the whole module and fails closed unless the name has exactly one possible writer, a top-level literal `frozenset` assignment (nor may `frozenset` itself be rebound), and names each writer it found and why it counts. `eval/caselib/__init__.py` may only re-export the names unchanged. Every ratchet the base's own copy of the checker lists must still be checked and readable in the base, so a ratchet can no longer be dropped, renamed or moved; ratchets are never retired or renamed by design (adding one is always fine), and an unreadable base fails closed. The tests that use the sets now read the literal the check verified instead of an imported global, and a test asserts `caselib`'s values equal that literal after import. The ratchets guard against accidental or unreviewed growth; deliberately malicious code in a pull request (edits to the checker, runtime code mutating test state) is left to the mandatory review — see eval/README.md's threat model.
- **`tests/test_case_library.py`**'s privacy allowlist: entries were `re.fullmatch` patterns screened for breadth by probe strings that don't look like real findings (the scrub reports `/Users/jsmith`, never a full path), so broad patterns such as `/Users/[^/]+`, `.+\.home`, `[^@]+@acme\.com` or a conditional group passed. Entries are now exact literals — `{"kind", "text", "reason"}`, matched with `==` against the finding — `model.Case` rejects any other shape, and every entry must match a finding its case actually produces. No case used the allowlist, so nothing else changes; the probe machinery is gone.
- **`eval/gallery/verdicts.py`**'s `load_results`: a scorecard row's `"crashed"` flag is true when *either* the reference or the candidate crashed, but `load_results` used it to decide whether to show the candidate's result at all — hiding a real candidate miss (exit 0) behind a reference-only crash instead of surfacing it as a miss. It now keys off the row's own `"candidate"` key (`None` exactly when the candidate itself crashed), shows the candidate's result as usual, and notes that the reference run crashed on that case.
- **`eval/gallery/build.py`**'s page-1 render caption: every `match.*` (layout-splitting) case was treated as visible on page 1, so `match.extreme-coordinates` (K35), whose text PyMuPDF's extraction never returns, rendered blank with no caption. Captions for `match.*` cases are now decided from the pages' extracted text, rule by rule, comparing letters and digits only: the whole value on one line gets no caption, the whole value on page 1 but only across lines gets "The value is on this page, split across lines", at least 3 characters on page 1 with the rest on a later page gets "Only part of the value is on page 1…", a value only on later pages gets "Not on page 1: the value appears later in the document", and one in no page's text gets "Nothing visible here". A rule with no literal value is judged by its own regex and validator, line by line or across joined lines. Captions say where the value is, not whether it is legible. A test pins the answer for every `match.*` leak case against a hand-checked table.

### Changed

**Redesign Phase 2, step 2 ("Move"): report, views** (#27): the page/OCR views and the report renderers moved out of `verify.py` too — `redaction_verifier/views/` (`text.py`: the layout-aware visual text extractor, `_reconstruct`/`_join_cluster`/`extract_visual_text`/`TEXT_GENUINE_READINGS` and the line-clustering constants; `ocr.py`: the Apple Vision bridge, `_vision_recognize_batch`/`extract_ocr_text`/`OCR_DPI`, and the one source of truth for `_OCR_IMPORTS_OK`) and `redaction_verifier/report/` (`text.py`: `_sanitize_report_text`/`print_report`; `json.py`: `build_json_report`/`write_json_report`/`JSON_SCHEMA_VERSION`); byte-identical `--json` and console output, no behaviour change. `redaction_verifier.views` imports `fitz` plainly (no guard of its own): a failure propagates out of the package and is caught by the same single guarded re-export block in `verify.py` that already covered a broken `redaction_verifier` import, so it still exits 2 rather than a bare traceback and exit 1. The Vision/Foundation import inside `views/ocr.py` keeps its ordinary-failure degrade (`except Exception: _OCR_IMPORTS_OK = False` → `OCR_UNAVAILABLE` warning, exit 2, OCR never silently skipped) but a BaseException there (SystemExit, KeyboardInterrupt, ...) no longer gets its own dedicated "cannot import the OCR bridge (Vision)" message — the package must never import `verify` to call its `_fatal_import` — and is now reported as the generic "cannot import redaction_verifier" instead; `tests/test_cli.py`'s import-guard tests were extended to cover both. `build_json_report` no longer owns the tool's version (`verify.__version__` is still the single source `pyproject.toml`'s dynamic version reads); its caller now passes it explicitly as `tool_version`. See `docs/REDESIGN.md` §4/§6/§7 (Phase 2).

**Redesign Phase 2, step 3 ("Move"): decouple tests from `verify.py`'s re-export** (#29): no code in `redaction_verifier` or `verify.py` changed — only what the test suite (and `eval/gallery/build.py`, `eval/caselib/run.py`, `eval/spikes/pattern_class_false_hard.py`) imports. Every reference to a name that Phase 2 steps 1–2 moved into the package (`ScanReport`, `Secret`, `SecretMatcher`, `PatternRule`, `normalize_string`, `BUILTIN_PATTERN_CLASSES`, the validators, `match_patterns`, `mask`, `load_rules`, `RuleSet`, `ENTITY_TYPE_TO_CLASS`, `VerifyError`, `Warn`, `WARNING_CODES`/`WARNING_FIELDS`, `LAYERS`, `STORAGE_CLASSES`, `extract_visual_text`, `TEXT_GENUINE_READINGS`, `_OCR_IMPORTS_OK`, `JSON_SCHEMA_VERSION`, `build_json_report`) now imports it from the `redaction_verifier` submodule that defines it, instead of reaching it through `verify.py`'s compatibility re-export (`verify.X`). `verify.py`'s re-export block itself is untouched — it still backs the CLI and external users until Phase 6 — and the monkeypatches that legitimately target `verify.<name>` (`print_report`, and the legacy object-scanning guards `_looks_binary`/`_strip_pdf_strings`/`_is_opaque_stream`/`_pdf_string_spans`) are unchanged, since their callers still live in `verify.py`. **Follow-ups: `pymupdf` migration, `_fatal_import` hardening, OCR/report wiring, doc NITs** (#31, closes #19, #23, #26, #28): `import fitz` became `import pymupdf as fitz` throughout `verify.py`, `redaction_verifier/`, `eval/caselib`, `eval/scorecard` and the tests (`eval/spikes` left as `fitz`, matching its own experimental scope) — a mechanical rename ahead of a future PyMuPDF release dropping the deprecated `fitz` alias. `--json` and console output are byte-identical before and after on generated case PDFs, except that the `fitz` alias's own "deprecated, use `import pymupdf`" line no longer leaks onto stdout ahead of the report; the scorecard diff is unchanged (10 accepted, 0 unlisted, 0 crashed). mypy now follows `pymupdf` (unlike `fitz`, it ships `py.typed`), which surfaced both a real issue (`redaction_verifier/views/ocr.py`'s `pix` reused as `None`, now released with `del pix` instead) and several spurious `attr-defined` errors from `pymupdf`'s incomplete bundled stubs (missing module-level constants, `Document.__iter__`); the latter are disabled narrowly, per affected module (`eval/caselib/pdfkit.py`, `families/{carriers,clean,live}.py`, `eval/scorecard/corpus.py`), not with a blanket skip of the whole package.
`verify.py`'s `_fatal_import` now flushes stderr and exits via `os._exit(2)` instead of `sys.exit(2)`: a dependency whose module body replaces `sys.exit` before raising (accidentally or adversarially) could otherwise turn the exit into a no-op and fall through into the rest of `verify.py` with none of its own imports bound. `os._exit` is a direct syscall such a module cannot intercept, so the import guards no longer depend on `run_cli`'s own `except BaseException: os._exit(...)` backstop to still exit 2.
`redaction_verifier.report.json.build_json_report` now takes `ocr_available` as an explicit keyword argument, threaded in by `verify.py`'s `main()` from its own `_OCR_IMPORTS_OK` (the same value that gates the OCR layer) — like `tool_version` — instead of importing `redaction_verifier.views._OCR_IMPORTS_OK` itself; output is unchanged. Tests now assert the JSON report's `ocr_available` field and pin `OCR_DPI`. A handful of stale comments (a removed `except BaseException` clause in an OCR-import test, `eval/caselib/run.py`'s Vision-import cross-reference, `report/json.py`'s `fitz`-safety note) were corrected, `tests/test_import_boundaries.py` now walks `tests/` recursively (`rglob`, not `glob`) for a future test subpackage, and a couple of continuation lines in `tests/test_objects.py` that lost their alignment in #29's mechanical rewrite were re-flowed.

### Verdict changes
The following changes can move a file's exit code:
- **Exit 0 → 2**: Files with compactly written content streams (no spaces between operators), long inline images or text in leftover streams without BT operators, or font-before-BT patterns in leftover streams (now properly tokenized). The scanner cannot certify these files as fully clean because it cannot reliably extract the content.
- **Exit 1 → 2**: An unexpected internal error in the tool now exits 2 (uncertifiable) unless a secret had already been found, in which case it stays 1 (leak). The JSON report includes `error.code` as `INTERNAL_ERROR` when applicable.
